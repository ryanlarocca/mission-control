# LRG e-sign — spec + runbook

Built 2026-10-17/18 on the Mac mini. A lightweight DocuSign for Ryan's
purchase agreements: send → seller signs on their phone → completed PDF with
a Certificate of Completion is emailed to everyone and filed in Drive.

- Code: `esign/` in this repo (plain Node ESM, no build step).
- Template: `esign/assets/template-reference.pdf`, generated by
  `esign/template/build_template.py` (README there has the build and the
  Drive `files.update` upload on the live file id). Fields the bot fills +
  the `addendum_attached` checkbox e-sign ticks.
- Data: `~/Projects/PROJECTS/esign/data/` (SQLite + per-envelope PDFs; outside
  the repo, gitignored by the `**/data/` rule in `~/Projects/.gitignore`).
  Per envelope: `original.pdf` (as sent, chmod 444, fingerprinted),
  `interim.pdf` (original + every signature so far — rebuilt after each
  signature, what later signers review), `pages/` (PNGs of the interim, or
  of the original until there is one), `signed.pdf` + `final.pdf` (built
  from the original at the end, chmod 444).
- Public: `https://sign.lrghomes.com` → named Cloudflare Tunnel `esign` →
  `127.0.0.1:5877`. No router ports opened; Cloudflare terminates HTTPS.
- Email: Gmail API as `ryan@lrghomes.com` through the Workspace service
  account (`GOOGLE_SERVICE_ACCOUNT_KEY`, same as Mission Control). Plain +
  HTML, dark-mode safe (every cell has an explicit `bgcolor`, every text run
  an explicit colour); the logo is `public/logo-email.png` — the logo
  flattened onto opaque white with 16px padding — inside a white tile, so
  Gmail's dark theme can't make it vanish.
- Static assets (`/style.css`, `/sign.js`, `/admin.js`, `/logo*.png`,
  `/fonts/*`) are content-hashed at startup (`lib/assets.mjs`): pages link
  `/style.css?v=<sha256 prefix>` and a matching `?v=` is served
  `public, max-age=31536000, immutable`; a bare or stale URL is `no-cache`.
  A deploy therefore never leaves a phone on an old stylesheet (Safari kept
  the previous CSS for an hour under the old `max-age=3600`).
- Alerts: Marketing bot → Ryan (`CAMPAIGN_BOT_TOKEN` / `TELEGRAM_CHAT_ID`).

## Flow

1. Ryan creates a request at `/admin/new` — pick a PDF from Drive
   `Business Operations/Offers/Drafts/<street>/` (or upload one), title, property,
   agreement date, note, signers (name, email, phone, Seller/Buyer, order).
   The offer bot's "📁 Saved to Drive" message carries a **✍️ Send for
   signature** button that opens this page pre-filled (seller + Ryan as buyer).
2. Signers in the lowest order tier get an email with a private link
   (`/s/<32-byte token>`, token stored hashed, expires `ESIGN_LINK_DAYS`=14).
   Same order number = sent together; the next tier is emailed when the
   previous one has all signed.
3. Link → consent screen (ESIGN/UETA disclosure, versioned in
   `lib/consent.mjs`; "I'd rather sign on paper" declines + alerts Ryan) →
   review (every page as a PNG, `pdftoppm` 110 dpi, plus a PDF link) with a
   yellow **Sign here** tab overlaid on the agreement's own signature line
   (template signers; addendum signers get a "Your signature" card). The
   pages are rendered from **`interim.pdf`** — the document with every
   signature applied so far (dates filled, signatures on the template lines,
   the Signature Addendum page(s) appended) — so a second-tier signer, and
   Ryan counter-signing as Buyer, review a copy that already carries the
   seller's ink; "Open as a PDF" (`/s/<token>/document.pdf`) is the same
   file. `envelope.view_page_count` is the interim's page count (original +
   addendum pages); `page_count` stays the original's for the certificate.
   The tab
   is 48px tall with its bottom edge exactly on the line: `.pagewrap` is
   the page image itself, the `.spot` anchor's top is the line in % of the
   page (`(792 − lineY) / 792`) and the tab hangs above it → tap →
   bottom sheet: full legal name (must contain a space), **Choose a style**
   (Great Vibes / Allura / Homemade Apple / Alex Brush, served as web fonts
   from `/fonts/`) or **Draw with your finger** → Adopt → signature shows on
   the page → "I have read…" box → green **Finish**. Fonts embed unsubsetted
   (Allura breaks under pdf-lib subsetting); variable TTFs render garbage —
   use static builds only.
3b. Delivery per signer: **email**, **text** (CRMS sidecar `POST
   127.0.0.1:5799/send` — iMessage then SMS from Ryan's own cell), or
   **both**. Email is optional when a cell number is given. Completion goes
   out as an email with the PDF attached (email signers + Ryan) and as a text
   with the `/verify/<id>` link (text signers).
4. Every open / sign / decline / expired-link hit records IP (Cloudflare's
   `cf-connecting-ip`), approximate location (ip-api.com), User-Agent, and
   posts a Telegram notice.
4b. After every signature (and once at creation when the envelope has
   addendum signers) `lib/envelope.mjs refreshInterim` rebuilds
   `interim.pdf` with `lib/pdf.mjs buildInterimPdf` — the same drawing as
   the final build (`applySignatures`), minus the certificate — re-renders
   `pages/` from it (into a fresh folder, then swapped) and updates
   `view_page_count`. A failure is logged as an `interim_failed` event and
   the next signer simply reviews the previous render; the signature itself
   is never undone. `original.pdf` is never touched.
5. When the last signer signs: `lib/pdf.mjs buildFinalPdf` loads the
   original and runs the shared `applySignatures`: fills the template's
   `seller_date` / `buyer_date` with each signer's signing date (PT); when
   the envelope has addendum signers, ticks the template's
   **`addendum_attached`** box ("Additional Seller(s) and/or Buyer(s) have
   signed the attached Signature Addendum…"; the names themselves are on
   the addendum, not page 2; skipped silently on envelopes created from
   the pre-2026-10-20 template, which has no box); flattens
   the form; draws the signatures on the template's own lines (first Seller
   + first Buyer by order; coordinates in `TEMPLATE`); appends a
   **Signature Addendum** page listing every other signer (header line
   "Referenced by the checked box on page 2 of the Agreement."; in the
   interim a signer who hasn't signed yet gets an empty line), saves
   `signed.pdf`, then appends the **Certificate of Completion** (envelope
   id, SHA-256 of the original and of `signed.pdf`, per-signer audit, event
   log) → `final.pdf`. Files are chmod 444 and the envelope row is `locked`
   — no route can change it afterwards. The admin detail page links the
   original, "Signed so far" (`/admin/e/<id>/interim.pdf`, while in
   progress) and, once completed, the signed + final files.
6. `final.pdf` is uploaded to Drive `Business Operations/Offers/Signed/<street>/`
   (same street folder name as the draft), emailed with the
   attachment to every signer + Ryan, and announced on Telegram. Delivery is
   idempotent: **Retry delivery** on the admin page redoes only what failed.
7. Signers can download their copy from the done page / completion email;
   `/verify/<envelope id>` shows status + fingerprints + download.

- Restart server: `launchctl kickstart -k gui/$(id -u)/com.lrghomes.esign`
  (after `git pull` on main; no build step).
- Backup (since 2026-10-24) = the Mac mini nightly backup
  (`scripts/mini-backup/`): a `VACUUM INTO` snapshot of `esign.sqlite` + the
  whole `data/envelopes/` tree → Drive `Business Operations/System/Mac Mini Backup/esign/`.
  The old `com.lrghomes.esign-backup` job (→ `E-Sign Backups/`) is retired;
  `scripts/backup.mjs` stays for a manual one-off. Drive filing: drafts
  `Offers/Drafts/<street>/`, signed copies `Offers/Signed/<street>/`.
- Secrets: `esign/.env.local` (gitignored) — `ESIGN_ADMIN_PASSWORD`,
  `ESIGN_API_SECRET`, `ESIGN_COOKIE_SECRET`, `ESIGN_BASE_URL`, `ESIGN_PORT`.
  Google + Telegram keys come from `mission-control/.env.local`.
- Dry runs: `ESIGN_DRY_MAIL=1 ESIGN_QUIET=1 ESIGN_DATA_DIR=/tmp/x ESIGN_PORT=5878
  node server.mjs` logs emails/notices instead of sending; signing links
  print in the log.
- Tests: `cd esign && npm install && npm run test:e2e` (`node --test
  tests/e2e.spec.mjs`). Boots a dry server on a free port with a temp data
  dir and drives the whole flow in Playwright's iPhone 13 emulation: admin
  upload → `original.pdf` == the uploaded file, interim already has the
  addendum box ticked → consent → typed (non-default style, tab on the
  seller line, 3 review pages) → the interim now carries the stamp, the
  same-tier seller's `document.pdf` is the interim → drawn (addendum card)
  → buyer invited only after both, reviews both sellers' signatures →
  completion → `final.pdf` fingerprint-matched, the tick (dark-pixel
  count in the box) + certificate's original fingerprint →
  verify page → admin detail. Needs Node ≥ 22.5, `pdftoppm`/`pdftotext`
  and Playwright's Chromium (`npx playwright install chromium` once on a
  new machine; the Mac mini has Homebrew poppler). ~20 s.
- JSON API: `POST /api/envelopes` with `Authorization: Bearer $ESIGN_API_SECRET`
  `{ title, property_address, agreement_date, message, drive_file_id |
  pdf_base64, signers:[{name,email,phone,role,order}] }` → `{ id, sent,
  admin_url }`.
- Sleep: the mini already runs `caffeinate` (sleep 0); nothing extra needed.

## Gotchas learned

- The template's light-blue boxes are drawn in the page content *and* in
  the widget appearance — they stay on the signed copy by design.
- pdfplumber's `y0` is the glyph bottom, not the baseline: Helvetica's
  descender is 0.207 em, so a 9.4pt line reported at 716.05 sits on
  baseline 718. Measure the template from the script's constants, not from
  a text dump.
- pdf-lib ticks a checkbox with `check()` + `updateFieldAppearances()`; the
  widget needs `/AP /N << /Yes /Off >>` streams in the template for the on
  value to exist. `flatten()` then paints the tick into the page.
- `fmtDatePT` treats `YYYY-MM-DD` as a calendar date (no timezone shift);
  only timestamps go through `America/Los_Angeles`.
- pdf-lib's `form.flatten()` keeps the fields' existing appearance streams;
  `updateFieldAppearances` only regenerates dirty fields.
- Git worktrees have no `.env.local`; `lib/env.mjs` falls back to the main
  checkout's file.
- `curl -F` treats a value starting with `(` as a nested-multipart marker —
  a phone like `(408) …` in a test post swallows every later field. Browsers
  are fine; write test phones without parentheses.
- Headless Chrome won't lay out narrower than ~500 px; a 390-px screenshot
  is a cropped 500-px page, not an overflow bug.
- A `hidden` attribute loses to `display:flex` in CSS — `[hidden]{display:none!important}`.
- Playwright's iPhone device emulation *does* lay out at 390 px (plain
  headless Chrome doesn't) — use `devices['iPhone 13']` for signer checks.
- HTTP header values must be ASCII: a `Content-Disposition` filename built
  from a title with an en dash (`Purchase Agreement – 1234 Main St`) made
  `writeHead` throw. `server.mjs contentDisposition()` sends an ASCII
  fallback plus `filename*=UTF-8''…`.
- Hidden text never triggers a web-font download, so the style cards in the
  closed sheet measured with the fallback font and clipped once the real
  one landed. `sign.js` calls `document.fonts.load()` for all four up front
  and re-fits the previews on `document.fonts.ready`.
- Percentage offsets inside `.pagewrap` are relative to its padding box —
  any margin/border on the `<img>` inside skews the tab by that much.
